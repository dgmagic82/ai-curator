# Логирование запросов и отчёт по темам

## Что пишется в лог

Каждый вопрос к куратору пишется отдельной строкой JSON в `logs/queries.jsonl` (`curator/logging_.py`).

| Поле | Пример | Зачем |
|---|---|---|
| `ts` | 2026-10-23T12:40:05+00:00 | динамика по дням и часам |
| `student_id`, `level` | s003, начинающий | кто спрашивает и на каком уровне |
| `module_filter`, `type_filter` | 3, лекция | как студенты сужают поиск |
| `question` | «Мне продлили ДЗ-2?» | сами вопросы, для разбора пробелов |
| `category` | организационный | доля типов вопросов |
| `escalate` | true | нагрузка на куратора-человека |
| `sources` | ["lms", "faq"] | какие материалы реально используются |
| `source_modules` | [0, 2] | к какому модулю относятся вопросы |
| `latency_ms`, `tokens_in`, `tokens_out`, `model` | 4400, 4100, 180 | скорость и стоимость |

Персональных данных, кроме вымышленного `student_id`, в логе нет. На реальной платформе вместо id стоит писать его хеш, а лог хранить ограниченный срок.

## Страница «Аналитика»

Страница строится по логу (`views/analytics.py`). Если лог пуст, она показывает пример: прогон 30 контрольных вопросов из `logs/sample_queries.jsonl`.

- **Сводка**: число вопросов, среднее время ответа, доля переданных человеку, доля ответов без источника.
- **Типы вопросов**: организационные, учебные, рекомендации, вне рамок.
- **Модули**: к каким модулям относятся использованные источники.
- **Самые цитируемые документы**: какие лекции, методички и разделы FAQ работают чаще всего.
- **Вопросы без источника**: главный сигнал для улучшения контента. Это вопросы, на которые в базе нет ответа.
- **Последние вопросы**: таблица для чтения глазами.

## Как читать отчёт и что с ним делать

| Сигнал | Что значит | Действие |
|---|---|---|
| Растёт доля «без источника» | студенты спрашивают то, чего нет в базе | дописать раздел FAQ или лекции, переиндексировать (`UPDATE_KB.md`) |
| Много учебных вопросов к одной лекции | тема трудная или плохо объяснена | переписать раздел, добавить пример, разобрать на вебинаре |
| Много организационных вопросов про дедлайны | расписание неочевидно | напоминания в чат потока, дедлайны на главной странице кабинета |
| Высокая доля передачи человеку | куратор-человек перегружен | посмотреть, какие вопросы можно закрыть правилами в FAQ |
| Растёт время ответа или токены | длинные фрагменты или история | сократить разделы, уменьшить `TOP_K` или `HISTORY_TURNS` |

Пример выводов по контрольному прогону (30 вопросов):
- организационные вопросы занимают 40%, и почти все они закрываются FAQ и данными LMS;
- чаще всего цитируются FAQ и LMS, из лекций лекция 3-3 об оценке RAG;
- вопросов без источника нет;
- 13% вопросов переданы человеку: продления, апелляции, академический отпуск.

## Структура периодического отчёта для команды курса

Отчёт делается раз в неделю на поток:
1. Объём: вопросов за неделю, студентов, доля учебных и организационных.
2. Топ-10 тем по `source_modules` и `sources`, рост к прошлой неделе.
3. Пробелы: вопросы без источника, сгруппированные по смыслу, и что дописать в базу.
4. Передано человеку: сколько и по каким причинам.
5. Качество: среднее время ответа, стоимость, результат последнего прогона eval.
