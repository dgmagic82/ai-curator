# Методичка к ДЗ-3: мини-RAG по своим документам

## Цель и срок ДЗ-3
В домашнем задании 3 вы собираете небольшую RAG-систему по своим документам и оцениваете её качество. Подходит любой набор из 5–15 текстов: инструкции с работы (без конфиденциальных данных), правила клуба, конспекты, описания товаров. Собирать можно кодом на Python или в Langflow, способ не влияет на оценку. Срок сдачи ДЗ-3: 16.11.2026 23:59 МСК. Правила переноса и пересдачи смотрите в FAQ курса.

## Как выполнить ДЗ-3 по шагам
1. Подготовьте документы: уберите служебный текст, проверьте, что разделы понятны сами по себе (лекция 3-2).
2. Разбейте документы на фрагменты и сохраните метаданные: как минимум идентификатор документа и заголовок раздела.
3. Посчитайте эмбеддинги фрагментов и сохраните их в векторное хранилище (лекция 3-1).
4. Соберите эталонный набор из 15 вопросов: простые, с перефразированием, требующие двух фрагментов и 3 вопроса, ответа на которые в документах нет. Для каждого запишите ожидаемый документ.
5. Напишите промпт генерации: отвечать только по фрагментам, указывать источник, честно отказывать при отсутствии ответа.
6. Прогоните все вопросы, сохраните найденные фрагменты и ответы.
7. Посчитайте recall@k для поиска и оцените ответы по обоснованности и корректному отказу (лекция 3-3).
8. Измените один параметр (размер фрагмента, k или промпт) и повторите оценку.

## Что сдать по ДЗ-3
Ссылка на репозиторий или архив ZIP через форму сдачи в личном кабинете. Внутри:
- код или экспорт схемы Langflow в JSON;
- документы или их описание, если тексты нельзя передавать;
- файл с эталонными вопросами и ожидаемыми источниками;
- таблица результатов: вопрос, найденные doc_id, ответ, оценка;
- README на одну страницу: как запустить, параметры разбиения, модель эмбеддингов, метрики до и после изменения, выводы.

Ключи API в сдаваемые файлы не включайте.

## Что проверяет проверяющий в ДЗ-3
- Система запускается по инструкции из README.
- Фрагменты хранят метаданные, ответ указывает источник.
- В эталонном наборе есть вопросы без ответа, и система на них отказывает.
- Recall@k посчитан, значение k указано.
- Проведено одно контролируемое изменение с замером до и после.
- Выводы объясняют хотя бы один конкретный провал поиска или генерации.

## Типичные ошибки в ДЗ-3
Эталонные вопросы списаны дословно из текста документов, и поиск выглядит лучше, чем есть. Нет вопросов без ответа, поэтому выдумки не обнаружены. Вопрос и документы закодированы разными моделями эмбеддингов. Таблицы разрезаны при разбиении, и числа потеряли заголовки. Ключ API оставлен в коде или в экспорте схемы. Оценивается только итоговый ответ, без отдельной проверки поиска.
