# Инструменты и вызов функций (function calling)

## Что такое инструмент для языковой модели
Языковая модель сама по себе только генерирует текст. Она не может узнать текущий курс валют, записать строку в таблицу или отправить письмо. Чтобы модель могла действовать, ей дают инструменты: функции, которые выполняет ваш код. Механизм называется вызовом функций (function calling) или использованием инструментов (tool use). Принципиальный момент: модель не выполняет функцию сама. Она лишь возвращает структурированный запрос «вызови функцию X с такими аргументами». Выполняет вызов ваш код, а результат передаётся модели обратно, чтобы она продолжила работу.

## Описание инструмента
Чтобы модель знала, какие инструменты доступны, в запрос к API передают их описания. Обычно описание состоит из имени, текстового пояснения и схемы параметров в формате JSON Schema. Точная структура полей отличается у разных провайдеров, поэтому сверяйтесь с документацией своего API. Общая идея выглядит так:

```
{
  "name": "get_homework_status",
  "description": "Возвращает статус проверки домашнего задания
    студента. Используй, когда студент спрашивает, проверена
    ли его работа. Не используй для вопросов о дедлайнах.",
  "parameters": {
    "type": "object",
    "properties": {
      "student_id": {"type": "string", "description": "ID студента"},
      "homework": {"type": "string", "enum": ["ДЗ-1", "ДЗ-2", "ДЗ-3", "ДЗ-4"]}
    },
    "required": ["student_id", "homework"]
  }
}
```

Описание инструмента фактически является промптом. Модель решает, вызывать ли функцию и с какими аргументами, только по тексту description и схеме. Поэтому пишите в описании, когда инструмент использовать и когда нет, ограничивайте значения через enum и делайте названия параметров понятными.

## Цикл вызова инструмента
Работа с инструментами идёт циклом из нескольких шагов.

1. Приложение отправляет модели сообщения пользователя и описания инструментов.
2. Модель отвечает либо обычным текстом, либо запросом на вызов инструмента с аргументами в виде JSON.
3. Приложение проверяет аргументы, выполняет функцию и получает результат.
4. Результат добавляется в историю сообщений с пометкой, к какому вызову он относится, и снова отправляется модели.
5. Модель формирует ответ пользователю или запрашивает следующий инструмент.

Цикл повторяется, пока модель не даст финальный ответ. Многие API позволяют модели запросить несколько вызовов в одном ответе, а также управлять выбором: разрешить модели решать самой, запретить инструменты или потребовать вызов конкретного инструмента. Названия этих настроек различаются у провайдеров.

## Проверка аргументов и обработка ошибок
Аргументы от модели нужно проверять так же, как любой пользовательский ввод: тип, обязательные поля, допустимые значения, права доступа. Модель может передать неверный идентификатор или попытаться получить данные другого пользователя, если её к этому подтолкнули. Если функция завершилась ошибкой, полезно вернуть модели понятный текст ошибки, а не обрывать диалог: модель часто может исправить аргументы и повторить вызов. Ограничьте число итераций цикла, чтобы ошибка не превратилась в бесконечную серию вызовов и расходов. Инструменты с необратимыми последствиями (оплата, удаление, отправка сообщений) стоит выполнять только после подтверждения человеком.

## От вызова функций к агенту
Агентом обычно называют систему, где модель в цикле сама выбирает, какие инструменты вызывать и в каком порядке, чтобы достичь цели. Такой подход часто описывают схемой ReAct: модель чередует рассуждение, действие (вызов инструмента) и наблюдение (результат). Агенту нужна чёткая цель, небольшой набор хорошо описанных инструментов и условия остановки. Чем больше похожих инструментов, тем чаще модель путает их, поэтому начинайте с минимума. Для подключения инструментов к разным приложениям существуют и общие протоколы, например Model Context Protocol (MCP), но базовый механизм под ними тот же: описание, вызов, результат.

## Главное из лекции
- Модель не выполняет функции сама, она возвращает запрос на вызов с аргументами.
- Описание инструмента работает как промпт: пишите, когда его использовать и когда нет.
- Цикл: запрос, вызов, выполнение кодом, результат обратно модели, ответ.
- Проверяйте аргументы, возвращайте понятные ошибки и ограничивайте число итераций.
- Агент это модель, которая в цикле сама выбирает инструменты для достижения цели.
