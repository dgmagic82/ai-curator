# Эмбеддинги и векторный поиск

## Что такое RAG и зачем ему поиск
RAG (Retrieval-Augmented Generation, генерация с опорой на найденные данные) решает две проблемы языковых моделей: модель не знает ваших внутренних документов и может выдумывать факты. Схема RAG простая. На вопрос пользователя система сначала ищет подходящие фрагменты в базе знаний, затем вставляет их в промпт и просит модель ответить только по ним. Качество всего RAG сильно зависит от первого шага: если поиск принёс не те фрагменты, даже лучшая модель ответит плохо. Для поиска по смыслу используют эмбеддинги и векторный поиск.

## Эмбеддинги: текст как вектор
Эмбеддинг это список чисел фиксированной длины (вектор), который отражает смысл текста. Его вычисляет отдельная модель эмбеддингов: на вход текст, на выход, например, несколько сотен или тысяч чисел. Модель обучена так, что тексты с близким смыслом получают близкие векторы. Фразы «как вернуть деньги за курс» и «процедура возврата оплаты» почти не совпадают по словам, но их эмбеддинги окажутся рядом. В этом главное отличие от поиска по ключевым словам. Важно: вопрос и документы нужно превращать в векторы одной и той же моделью эмбеддингов. Векторы разных моделей несовместимы, и при смене модели всю базу пересчитывают.

## Мера близости векторов
Чтобы найти похожие тексты, нужно сравнить векторы. Чаще всего используют косинусное сходство: косинус угла между двумя векторами. Значение близко к 1, когда векторы смотрят в одну сторону, то есть тексты близки по смыслу, и уменьшается по мере расхождения смыслов. Если векторы нормированы (их длина равна 1), косинусное сходство совпадает со скалярным произведением, и многие системы считают именно его, потому что это быстрее. Ещё одна мера: евклидово расстояние, где меньшее значение означает большую близость. Абсолютные значения сходства зависят от модели, поэтому порог вроде «считать релевантным всё выше 0,8» подбирают экспериментально на своих данных, а не переносят из чужих примеров.

## Векторный поиск и индексы
Векторный поиск находит k векторов из базы, ближайших к вектору запроса (top-k). На небольшой базе в тысячи фрагментов можно просто сравнить запрос с каждым вектором, это точный поиск. На миллионах векторов полный перебор становится медленным, и используют приближённый поиск ближайших соседей (ANN). Его реализуют специальные индексы, например графовый алгоритм HNSW. Приближённый поиск может изредка пропустить настоящего ближайшего соседа, зато работает на порядки быстрее. Хранят векторы в векторных базах данных или в библиотеках поиска; многие из них также умеют хранить метаданные и фильтровать по ним до или после поиска.

Упрощённый процесс поиска в псевдокоде:

```
# индексация (один раз)
для каждого фрагмента документа:
    вектор = embed(фрагмент.текст)
    база.добавить(вектор, фрагмент.текст, фрагмент.метаданные)

# поиск (на каждый вопрос)
вектор_запроса = embed(вопрос)
найденные = база.найти_ближайшие(вектор_запроса, k=4)
```

## Гибридный поиск и переранжирование
Векторный поиск хорошо ловит смысл, но может промахиваться на точных совпадениях: артикулах, номерах, редких терминах, датах. Классический поиск по ключевым словам, например алгоритм BM25, наоборот, силён в точных совпадениях. Гибридный поиск объединяет результаты обоих способов. Ещё один распространённый приём: переранжирование (reranking). Сначала векторный поиск быстро достаёт, скажем, 20 кандидатов, затем более точная, но медленная модель-ранжировщик оценивает пару «вопрос и фрагмент» и оставляет лучшие 3–5. Найденные фрагменты затем вставляют в промпт:

```
Ответь на вопрос студента, используя только фрагменты ниже.
Если ответа во фрагментах нет, скажи: «В материалах курса
этого нет, уточните у куратора». Укажи doc_id источника.

Фрагменты:
{найденные фрагменты с doc_id}

Вопрос: {вопрос}
```

## Главное из лекции
- RAG сначала ищет фрагменты в базе знаний, затем отвечает по ним.
- Эмбеддинг это вектор, близкие по смыслу тексты получают близкие векторы.
- Вопрос и документы кодируются одной моделью эмбеддингов.
- Близость обычно меряют косинусным сходством, порог подбирают на своих данных.
- Гибридный поиск и переранжирование повышают точность выдачи.
